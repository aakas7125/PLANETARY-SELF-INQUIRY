# Specialist agent onboarding and HQ attestation

Effective 2026-10-26. Owner direction; operational procedure under `OWNER_CONTROL.md` and `project-state/UNIVERSAL_ISSUE_CONTROL_PLANE.md`. A fresh agent is an execution instance of the existing Research & Evidence or AP Framework & Corpus workstream. It gains no separate authority. GitHub Issues remain task authority; the specialist returns through the required branch/PR and never self-merges. HQ independently accepts or returns the result. This procedure changes no Constitution, Owner Control, accepted source package, AP/scientific semantics, or executor authority.

## Before delegating substantive work

1. HQ checks fresh Issues, PRs, accepted contracts and task-specific overlap. Identify current governing and specialist files **by path and blob/revision**, including relevant frozen packages, workstream instructions/handoffs, prior findings, provenance and unresolved dependencies. Read the portions needed to explain this exact task; do not infer contents from filenames or old chat summaries. Note any context that exists only in an older chat and whether it was actually retrieved. Reuse a prior verified inventory for unchanged contracts, checking revision and material changes.
2. HQ gives the agent the exact references, task ID and accepted starting boundary, explains what Research may verify versus what AP may attribute/interpret, the deliverable and return path, disallowed adoption, required validation and HQ acceptance. A link in the prompt is an instruction to inspect, **not proof of a read**.
3. Before analysis/editing, the agent opens the relevant materials, reports actual sections/versions read, missing access, contradictions and older-chat context it could or could not inspect. HQ resolves a material gap before substantive execution. A fresh clone of an old workstream chat is not implied.
4. The Issue or HQ handoff records the pre-execution attestation below. If a verified file is unchanged, cite the earlier attestation and recheck the blob, then add only task-specific sources and dependencies. Do not require a broad re-audit of unrelated packages.
5. At return, HQ checks the exact diff/head, source and provenance claims, relevant rules, agent's read confirmation and remaining gaps against the deliverable. An agent's self-report alone is insufficient. Correct or qualify findings when a missed context changes the result. Record actual validation/hosted-check state, acceptance scope and any unresolved context before a qualifying merge.

## Attestation fields in the task Issue or handoff

- **HQ inventory before delegation:** task ID; main revision; governing/specialist paths and blob IDs or pinned revisions; prior reports/handoffs and active dependencies inspected; any reused prior inventory.
- **Agent guidance:** exact references and task-specific science/AP boundaries, deliverable, permissions, prohibition on adoption/self-merge and return/acceptance criteria.
- **Agent confirmation before execution:** actually opened paths/sections and revisions, conflicts, inaccessible originals or older-chat context; distinguish read from merely linked/inherited.
- **HQ reconciliation:** material gaps resolved before work, or reason to block; at return, independent exact-head/source checks and whether the recorded onboarding was followed.
- **Acceptance limit:** what report is accepted, what remains unverified, and whether any separate domain/product decision is still required.

No invented access: if an agent started before these checks, label the record retrospective, state precisely what was and was not read, and assess the already returned work on its evidence. A later read does not retroactively satisfy the pre-execution gate. If a missing document could change a conclusion, reconcile it and correct the report before relying on that conclusion.

For Research tasks, applicable files commonly include the empirical contract/source provenance for the actual claim, prior Research audits and relevant AP source metadata; do not grant AP attribution. For AP tasks, inspect the accepted AP interaction contract, frozen corpus provenance rules and relevant AP handoffs; do not use AP attribution to validate an empirical number. Apply the Constitution's separation, non-diagnosis and unknown-is-not-zero rules in both cases.
